# Driveway Gates London — silo plan

Live site, reconciliation and gap-fill. UK English, £ GBP; the lead form is the only
CTA (no phone). Titles are provisional — SERP/PAA-validate before writing.

## Local focus (what this site is built to own)

1. **Dropped-kerb / vehicle crossover by borough** — the gate is useless without
   legal vehicle access; each borough runs its own crossover scheme, classified-road
   triggers, ~8-12 week timelines, minimum frontage depth (~4.8m / 5m×2m bay).
2. **Front-garden paving + SUDS / ~25% permeable rule** — London's paved-frontage
   reality; gate projects bundle with re-laying the frontage.
3. **Terraced space-saving systems** — bi-fold, telescopic, cantilever for sub-5m
   frontages; outward-swing pavement-encroachment rules.
4. **Dense-street power supply** — long SWA runs, voltage drop, surface
   reinstatement, party-wall cable routing.
5. **Article 4 / conservation-area density** (14+ Article 4 boroughs; up to 67
   conservation areas per borough). This site also targets the generic
   "planning permission for driveway gates" head term.

**No new service pillar (resolved 2026-06-22).** The live matching model connects
homeowners only to independent gate installers and states "we do not carry out
installations ourselves"; the network does NOT cover council vehicle-crossover or
footway works. So the crossover + front-garden cluster is built as INFORMATIONAL
guides and blog under `/services/automated-gate-systems/` — capturing the
high-intent crossover/SUDS search and routing it to a gate quote, not a service
page promising work the network cannot fulfil.

## Sub-hubs — normalized to 8 core silo sub-hubs

This site runs more service pillars, so the silo is normalized on six core silo
pillars; the other services keep their existing guides as supporting. Lead pillar =
Automated Gate Systems, which carries the informational crossover/SUDS cluster (no
separate crossover service pillar — the gate network does not fulfil council
crossover works). Flagship = generic planning permission.

1. Sliding (space-saving) → `space-saving-gates-tight-driveways-london` (new)
2. Wrought-iron (heritage) → `conservation-area-gate-design-london` (new)
3. Access control → `best-intercom-systems` (existing)
4. Automated → `electric-driveway-gates-cost-london` (existing)
5. Automated also carries the lead cluster → `dropped-kerb-vehicle-crossover-london`
   + `front-garden-paving-suds-london` (both new, INFORMATIONAL — crossover work is
   council-licensed and outside the gate network; routes to an automated-gate quote)
6. Repair → `winter-gate-maintenance` (existing, servicing)
7. Flagship (cross-cutting) → `planning-permission-driveway-gates-london` (generic
   planning) — PROPOSED / build: the live site has no such guide URL; planning
   currently lives only in blog posts, so this sub-hub is net-new.

The other existing guides (running-costs, kit-prices, aluminium-vs-wooden,
swing-vs-sliding, safety-laws, force-testing, photocells, manual-open, motor-humming)
stay live as supporting guides; several are national/generic and sit outside the
core silo.

## Priority spokes — lead clusters first

**Crossover / frontage (the flagship, mostly NEW):** do I need a dropped kerb for a
gate; vehicle-crossover cost and timeline; minimum driveway depth for a gate;
front-garden paving permeable/SUDS rules; CPZ and the value of secured off-street
parking.

**Space-saving (mostly LIVE, re-ground to London frontages):** bi-fold vs sliding
for a short driveway; telescopic gates for a small driveway; cantilever sliding on a
narrow plot; can driveway gates open outwards (pavement rule); automated gates on a
sloping driveway.

**Conservation / heritage (LIVE):** conservation-area gate planning; Article 4 and
PD rights; tree-preservation-order front gardens; restoring Victorian wrought-iron;
period-frontage gate design.

**Power (NEW):** running power to a gate with no boundary mains; solar automation in
dense streets; SWA cable + surface reinstatement.

## One query per page (no internal cannibalisation)

Every guide and spoke owns exactly one reserved primary query; no two pages target
the same query. This site's national-query bids are generic planning permission and
the safety-law / force-testing / manual-release / motor-humming how-to content. Keep
generic product comparisons (intercom brand vs brand) thin — they compete with
national aggregators and convert poorly by geo.

## Build order

1. Crossover/frontage flagship cluster (2 sub-hubs + 5 spokes under Automated).
2. Space-saving cluster (re-ground existing live posts).
3. Conservation cluster (already strong, tighten links up to pillars).
4. Power cluster.
Location pages localised last.
